## 1. 项目背景与目标

### 1.1 背景

安仕平（Edwin）拥有 16 年软件研发经验，历任研发工程师、研发经理、架构设计师，主导过十年老旧单体系统的微服务重构、端到端 CI/CD 体系建设等工作。现有简历为 Word 文档，仅适合投递场景，无法承载长期的技术展示与学习研究沉淀。

### 1.2 目标

建立个人品牌网站，达成三个目标：

| 优先级 | 目标 | 说明 |
|---|---|---|
| P0 | 展示个人信息 | 一屏内让人快速理解「我是谁、我做什么、我擅长什么」 |
| P0 | 展示工作经历 | 完整、可信、可验证的职业履历与项目成果 |
| P0 | 承载学习研究 | 学习笔记、架构复盘、技术分享与阅读记录的长期归档容器，**内容后续补充，但结构必须预留** |
| P1 | 建立可信度 | 数据说话（≤200ms、≥90% 覆盖率、12 人团队），避免形容词堆砌 |
| P2 | 可被搜索引擎收录 | 基础 SEO + 结构化数据 |

### 1.3 非目标（本期不做）

- 不做后台管理系统 / CMS（内容以文件形式维护，Git 提交）
- 不做用户注册、评论、点赞等社交功能
- 不做多语言切换（预留英文摘要位，但本期只出中文）
- 不做博客系统（学习研究区块先用卡片列表承载，形态可后续演进）

### 2.1 用户画像

|---|---|---|---|
| 招聘方 / HR | 收到简历后点击链接核验 | 履历真实性、年限、稳定性 | 30–90 秒 |

| 同行 / 潜在合作方 | 搜索或社交链接进入 | 专业判断、学习研究、联系方式 | 1–5 分钟 |
| Edwin 本人 | 维护内容 | 加一条学习研究是否方便 | — |

### 2.2 关键路径

1. 落地页首屏 → 3 秒内判断「这是谁、是不是我要找的人」

3. 工作经历 → 逐条展开，重点看最近 2 段
4. 学习研究 → 查看具体条目，点击链接

## 3. 视觉与设计方向

### 3.1 设计关键词

**科技感 · 高级感 · 简洁**

三者之间的取舍原则：

- **科技感**来自「精度」而非「特效」：细线网格、等宽字体标注、精确的对齐、克制的动效
- **高级感**来自「留白」与「克制」：大留白、少颜色、低饱和、高质量字距行距
- **简洁**来自「减法」：每个区块只讲一件事，不堆图标、不堆装饰

### 3.2 明确禁止（Anti-patterns）

- ❌ 渐变紫蓝大色块堆砌、玻璃拟态滥用
- ❌ 粒子特效满屏飞、鼠标跟随光斑
- ❌ 滚动视差过度导致眩晕
- ❌ 圆角过大（>16px）、阴影过重
- ❌ 无意义动画（每个元素进入都 fade-in-up）
- ❌ 视差背景大图、AI 生成插画

### 3.3 视觉基调（待风格确认后锁定，详见第 9 章）

> 三个候选风格见 `STYLE-REFERENCES.md`，选定其一后在此处锁定具体色值、字体、间距。

## 4. 信息架构

```
/                      首页（单页滚动）
├── #hero              首屏：姓名 / 定位 / 一句话价值 / 主 CTA
├── #about             关于：基本信息 + 职业理念
├── #experience        工作经历：时间轴
├── #skills            技术能力：分组标签
├── #learning          学习研究：卡片列表（核心预留区）
└── #contact           联系方式（可并入 footer）
```

**导航策略**：顶部固定细导航条，高度 ≤64px，仅 4–5 个锚点，滚动时轻微下沉阴影；移动端折叠为等宽文字链接（不做汉堡菜单抽屉，保持简洁）。

## 5. 页面模块详细需求

### 5.1 首屏 Hero（P0）

**内容**

| 元素 | 内容 | 规则 |
|---|---|---|
| 姓名 | 安仕平 | 最大字号，主视觉 |
| 英文名 | Edwin | 次要，可作点缀 |
| 定位 | 系统架构设计师 · 高级工程师 · 研发经理 | 一行，强调色 |
| 价值主张 | 一句话，≤40 字，强调「架构设计 + 微服务重构 + 工程效能」 | 正文色，最大宽度 60ch |
| 关键标签 | 3–5 个（系统架构设计 / 微服务重构 / DevOps / 团队管理） | 小号标签，细边框 |
| 主 CTA | 查看学习研究 | 强调色实心按钮 |
| 次 CTA | GitHub / CSDN | 描边按钮或文字链接 |
| 头像 | 圆形或方形，后续提供 | 暂无则用姓名首字占位，不使用随机生成人像 |

**验收标准**

- 桌面端 1440×900 下，首屏无需滚动即可看到姓名、定位、价值主张、CTA
- 移动端 375×667 下，首屏可见姓名 + 定位 + CTA
- 无布局抖动（CLS < 0.05）

### 5.2 关于（P0）

**内容**

- 基本信息网格：学历、专业资格、外语、邮箱、社交主页及脱敏电话号码
- 电话号码只展示脱敏值，不提供拨号链接；完整号码不进入站点文件
- 职业理念引用块：「做人 / 做事 / 相信」三句
- 一段 80–120 字的自我描述，突出：自我驱动、逻辑严谨、责任心、团队协作、英语能力

**规则**

- 不使用头像大图
- 理念块用左侧强调色竖线区分，不做卡片堆叠

### 5.3 工作经历（P0）

**结构**：垂直时间轴，倒序（最近在前），共 6 段。

**每条包含**

| 字段 | 必填 | 说明 |
|---|---|---|
| 公司名 | ✅ | 最近一段使用已确认的 `Solera`；其它经历使用公司名 |
| 职位 / 部门 | ✅ | |
| 时间区间 | ✅ | `YYYY.MM — YYYY.MM` 或 `至今` |
| 职责摘要 | ✅ | 1–2 句 |
| 关键成果 | ✅ | 3–7 条 bullet，**优先保留量化数据与奖项** |
| 技术栈 | ✅ | 标签形式，小号，弱化处理 |

**交互**

- 默认全部展开（招聘方会直接读，折叠会增加操作成本）
- 若单页过长，可对 6 段中较早的 3 段做「收起」处理，但最近 3 段必须展开
- 时间轴节点在进入视口时轻微高亮，不做过场动画

**内容规则**

- 保留原始简历的全部事实，不编造、不夸大
- 数字表述统一：`≤200ms`、`≥90%`、`12 人`、`5 个项目`
- 奖项用加粗突出

### 5.4 技术能力（P1）

**结构**：按领域分组的标签云（非进度条、非百分比）

| 分组 | 内容 |
|---|---|
| 后端与架构 | .NET / C#、.NET Core、.NET Framework、ASP.NET MVC、WCF、Dapr、微服务、分布式架构、Python |
| 前端与客户端 | Angular、React、Vue、TypeScript、WPF、WinForm、Silverlight、MEF、GIS 集成 |
| 数据与中间件 | SQL Server、MySQL、Redis、RabbitMQ、Elasticsearch、Cassandra、NiFi、Liquibase |
| DevOps 与云原生 | K8s、ArgoCD、Tanzu、Helm、Docker、Jenkins、CI/CD、Nginx、Shell、Grafana、Graylog、SonarQube |
| 安全与治理 | Keycloak、Vault、Kong、Config-Server、身份认证、密钥管理、流量管控 |

**规则**

- **禁止使用技能条 / 百分比**（既不可信也显廉价）
- 标签按使用年限或熟练度排序，不随机
- 单标签文字 ≤12 字

### 5.5 学习研究（P0 · 核心预留区）

> **这是本站与普通简历页的核心差异点，必须设计为可长期扩展的容器。**

**数据结构（每条学习研究）**

```json
{
  "title": "标题",
  "type": "学习笔记 | 架构复盘 | 技术分享 | 开源实践 | 读书笔记",
  "date": "2026-10",
  "venue": "学习场景 / 分享活动 / 阅读来源",
  "authors": ["作者（可选）"],
  "summary": "摘要，50–120 字",
  "tags": ["架构", "微服务"],
  "links": [{"label": "阅读", "url": "..."}],
  "isExample": false
}
```

**展示规则**

- 卡片列表，按时间倒序
- 卡片包含：类型徽章、标题、时间、来源、摘要、标签、链接
- 测试数据带“示例”徽章和页面级说明，避免被误认为正式成果
- 空状态：显示「学习研究整理中」的克制占位 + 说明文案，不要显示「暂无数据」
- 预留筛选能力（按类型筛选），条目 < 5 条时不显示筛选器

**扩展路径（本期只预留，不实现）**

- 条目 > 20 条时，演进为独立页面 `/learning/` + 分页
- 单条内容可展开为详情页 `/learning/{slug}`

**内容维护方式**

- 本期：学习研究以结构化数据写在 `data/learning.js`，主页面读取渲染
- 新增内容 = 在数据文件中追加一条 + 本地预览确认 + Git 提交，无需改动页面结构

### 5.6 页脚 / 联系（P1）

- 一行链接：GitHub、CSDN、邮箱
- 版权行：`© 2026 安仕平`
- 不做超大「Let's talk」CTA 区域（与简洁定位冲突）

## 6. 交互与动效规范

| 项 | 规范 |
|---|---|
| 滚动 | 原生平滑滚动；锚点跳转留出导航高度偏移 |
| 进入动画 | 仅区块标题与卡片有极轻的位移+淡入（≤12px、≤300ms），且尊重 `prefers-reduced-motion` |
| 悬停 | 链接颜色变化、按钮亮度变化、卡片边框变色；**不做缩放、不做位移** |
| 导航 | 滚动 >20px 时加细分隔线；当前区块高亮 |
| 滚动进度 | 可选：顶部 2px 细进度条（若采用工业极简风格则开启） |
| 加载 | 无 loader 动画；静态资源直出 |

**性能预算**

- 首屏渲染 < 1.5s（4G）
- 总资源 < 300KB（不含头像）
- 无外部重型依赖（无 Tailwind CDN、无大型 JS 框架、无 Google Fonts 阻塞加载）

## 7. 技术方案

### 7.1 实现方式

**方案 A（已采用）：单页静态 HTML + CSS + 原生 JS**

- `index.html` + `styles.css` + `main.js` + 结构化的 `data/*.js`
- 零构建、零依赖，双击即可打开，任意静态托管可部署（GitHub Pages / Vercel / Netlify / 阿里云 OSS）
- 优点：最简、最稳、加载最快、长期可维护
- 缺点：条目多时需手工分页
- 页面文字、导航、CTA、技能、经历与学习研究均从 `data/` 读取，HTML 只保留渲染容器

**方案 B：Astro / Eleventy 静态生成**

- 适合学习研究演进为独立页面集合后迁移
- 本期不采用，作为 5.5 提到的扩展路径

├── assets/

### 7.3 兼容性

- Chrome / Edge / Safari / Firefox 最近 2 个大版本
- iOS Safari 15+、Android Chrome 100+
- 支持深色模式（`prefers-color-scheme`），深浅两套色值都需定义
- 支持 `prefers-reduced-motion`

### 7.4 可访问性

- 语义化标签（`nav` / `main` / `section` / `article` / `footer`）
- 所有图片有 `alt`
- 正文对比度 ≥ 4.5:1，大字 ≥ 3:1
- 键盘可完整遍历，焦点样式可见（不使用 `outline: none`）
- 锚点链接可被屏幕阅读器朗读

### 7.5 SEO

- `<title>`：`安仕平 · 系统架构设计师 | 个人主页`
- `meta description`：≤160 字，含职位与 16 年经验
- Open Graph + Twitter Card（分享卡片）
- 结构化数据 `Person`（JSON-LD）：name、jobTitle、email、url、sameAs
- 语义化标题层级 h1 → h2 → h3，不跳级

## 9. 风格方案选择（已决策）

详见 `docs/STYLE-REFERENCES.md`，三个候选：

| 方案 | 名称 | 关键词 | 适合度 |
|---|---|---|---|
| A | **Obsidian Grid**（黑曜石网格） | 近黑底色、细网格、等宽字体标注、青绿单色强调 | ★★★★★ 科技感最强，最贴近「架构师」气质 |
| B | **Paper White**（纸白极简） | 白底、大留白、极小字号导航、黑色强调、几乎无动效 | ★★★★☆ 高级感最强，最稳重 |
| C | **Slate Terminal**（石板终端） | 冷灰底、琥珀色强调、终端式标注、状态栏细节 | ★★★★☆ 有个性，技术味稍重 |

> 建议：主站用 A 或 B；若希望「面试官一眼觉得专业且不过时」，选 B，把科技感放在细节（等宽数字、细网格）里。

**已锁定**：Paper White 骨架 + Obsidian 青绿强调 + Mono 元信息，具体 token 见 `assets/styles.css`。
